**CQD (Ceresit Queue Daemon)** — це відкритий високопродуктивний моноліт та екосистема веб-інтерфейсів в індустріальній естетиці **Nothing** для диспетчеризації, операційного обліку та сповіщення черги колірування лакофарбових матеріалів і штукатурок у реальному часі.

Проєкт створено як незалежний некомерційний **pet-project Made For STEN** для автоматизації реального пункту колірування: усунення паперових записів, надання клієнтам живого статусу замовлення прямо на смартфон без дзвінків та надійного захисту локального обладнання за моделлю суворої двоконтурної мережевої ізоляції.

> [!NOTE]
> **Open Source Pet Project для спільноти (MIT License)**  
> **Made For STEN** — це незалежна авторська розробка, створена для комюніті мейкерів, колористів, малого бізнесу та ентузіастів чистого коду на Rust.  
> Проєкт **не є** комерційним чи офіційним продуктом компаній Ceresit / Henkel — це відкрите програмне забезпечення, доступне кожному для вивчення, адаптації під власні потреби, крафтові майстерні чи виробничі процеси.

## 1. Філософія та місія для комюніті

Більшість систем для складів, майстерень та пунктів видачі страждають від трьох хронічних проблем:
1. **Переускладненість та залежність від хмари:** щомісячні підписки, важкі фреймворки, повільне завантаження на мобільних пристроях і повна зупинка роботи при обриві зовнішнього інтернету.
2. **Нудний утилітарний дизайн:** сірі таблиці з 90-х років, дрібні кнопки, незручні для роботи в рукавицях чи на сенсорних планшетах.
3. **Мережева вразливість:** винесення адмінок і внутрішніх панелей прямо в публічний інтернет, що створює ризики несанкціонованого втручання.

**CQD створено як альтернативний маніфест відкритої інженерії:**
* **100% автономність (Zero Cloud Dependency):** весь проєкт компілюється в один статичний бінарний файл за допомогою `rust-embed`. Для роботи потрібен лише цей бінарник та локальна база даних SQLite. Жодних Node.js, зовнішніх веб-серверів чи зовнішніх СУБД.
* **Естетика та ергономіка Nothing:** темний інтерфейс AMOLED `#000000`, шрифтова матриця, приємні звукові та вібраційні сигнали зворотного зв'язку, що перетворюють рутинну роботу оператора на естетичне задоволення.
* **Відкритий код без прив'язок:** система повністю відкрита для комюніті під ліцензією MIT — беріть, модифікуйте та використовуйте безкоштовно.

## 2. Архітектурний пайплайн (Dual-Port Security)

Система працює за моделлю повної ізоляції контурів: публічні клієнти та внутрішні робочі місця обслуговуються різними асинхронними слухачами на різних мережевих портах.

```

                                                │
                                                ▼  Тільки публічні запити
                   ┌──────────────────────────────────────────────┐
                   │               CQD RUST MONOLITH              │
                   │                                              │
                   │  ┌────────────────────────────────────────┐  │
                   │  │ Публічний Слухач (:8080)               │  │
                   │  │ - Табло черги (Live Queue Monitor)     │  │
                   │  │ - Персональний трекінг (/track/{token})│  │
                   │  │ - W3C Web Push реєстрація              │  │
                   │  │ - 301 Honeypot (Rickroll на сканери)   │  │
                   │  └────────────────────────────────────────┘  │
                   │                                              │
                   │  ┌────────────────────────────────────────┐  │
                   │  │ Внутрішній Слухач (:8081 — LAN ONLY)   │  │
                   │  │ - Диспетчерська панель (/dispatcher)   │  │
                   │  │ - Сенсорний термінал (/terminal)       │  │
                   │  │ - Створення, черга, видалення партій   │  │
                   │  │ - Статистика та тоннаж зміни           │  │
                   │  └───────────────────▲────────────────────┘  │
                   │                      │                       │
                   │  ┌───────────────────┴────────────────────┐  │
                   │  │ Ядро: Tokio Runtime + SQLite (WAL)     │  │
                   │  │ + Криптографічний Event Sourcing       │  │
                   │  │ + Web Push VAPID ECDSA P-256 Engine    │  │
                   │  └────────────────────────────────────────┘  │
                   └──────────────────────▲───────────────────────┘
                                          │ Довірена мережа
                                          │ 192.168.88.0/24 / VPN
                                          │
                   ┌──────────────────────┴───────────────────────┐

                   └──────────────────────────────────────────────┘
```

## 3. Модулі та користувацькі інтерфейси

### 3.1. Публічне Табло Черги (`https://cqd.yunexal.com/`)
* **Призначення:** монітор для клієнтів у залі видачі та на смартфонах.
* **Дизайн:** естетика Nothing, чорний монохром, індикатор пульсу активності черги, великі цифри у крапковому шрифті `Doto`.
* **Секції черги:**
  1. `01. ГОТОВО ДО ВИДАЧІ` (білі картки з підсвічуванням та пульсуючим маяком готовності).
  2. `02. У ВИРОБНИЦТВІ (КОЛІРУВАННЯ / МІКСЕР)` (картки з індикацією поточного відра).
  3. `03. ОЧІКУЮТЬ РЕЦЕПТА` (черга замовлень у черзі на опрацювання).
* **Картка замовлення:**
  * Ім'я клієнта шрифтом `Unbounded` з оптимізацією від розриву слів на мобільних пристроях будь-якої ширини.
  * Чіп бази (`База A`, `База B`, червоний акцент `База C`).
  * Матеріал, колекція відтінку, вага фасування.
  * Крапкова матриця прогресу відер (micro-dots) та статусний бейдж.
  * Пряме посилання на персональний трекінг замовлення.

### 3.2. Персональний Трекінг Клієнта (`/track/{token}`)
* **Призначення:** індивідуальна сторінка для клієнта (відкривається за прямим посиланням або QR-кодом).
* **Етапи замовлення (Step Indicator):**
  1. `01. ЗАМОВЛЕННЯ ЗАРЕЄСТРОВАНО`
  2. `02. ТЕХНОЛОГІЧНА КАРТА` (передача рецепта в роботу)
  3. `03. КОЛІРУВАННЯ & МІКСЕР` (дозування пігментів та змішування)
  4. `04. ГОТОВО ДО ВИДАЧІ` (продукцію заколіровано та підготовлено)
* **Web Push сповіщення:** кнопка `СПОВІСТИТИ КОЛИ БУДЕ ГОТОВО`. Працює на базі стандарту W3C Push API / VAPID ECDSA P-256 без встановлення сторонніх додатків прямо у мобільних браузерах (Android Chrome, iOS Safari 16.4+).

### 3.3. Диспетчерська Панель (`/dispatcher`)
* **Метричні віджети:** `01. АКТИВНА ЧЕРГА`, `02. ВАГА ПАРТІЙ`, `03. ГОТОВО ДО ВИДАЧІ`.
* **Форма швидкої реєстрації:**
  * Поле клієнта (автодоповнення з раніше збережених).
  * Вибір матеріалу Ceresit (ґрунтовки CT 16 / CT 16 Pro, штукатурки CT 174, CT 60, CT 74, фарби CT 48, CT 54 тощо).
  * Інтерактивні чіпи бази відра: `[База A]`, `[База B]`, `[База C]`, `[Інша]`.
  * Фасування (`25 кг`, `15 кг`, `10 л`, `5 л`, `2.5 л`, `1 л` або власне).
  * Кількість відер у партії та код кольору.
* **Журнал виробництва:** живий пошук замовлень, статуси, прямий перехід у трекінг та функція видалення.

### 3.4. Сенсорний Термінал Колориста (`/terminal`)
* **Головний екран:** черга партій у вигляді горизонтальної смуги чіпів.
* **Картка активної партії:** великий шрифт клієнта, рецепт, база відра, фасування.
* **Керування процесом:**
  * `01. ВЗЯТИ В РОБОТУ` — переведення партії у стан активного колірування.
  * Велика кнопка `+1 ВІДРО` — фіксація заколірованого відра з вібраційним відгуком.
  * Кнопка `↺ ВІДМІНИТИ (-1 ВІДРО)` — захист від випадкового натискання.
  * `ГОТОВО ДО ВИДАЧІ` — фіксація готовності та автоматична розсилка Web Push клієнтам.
  * `КЛІЄНТ ЗАБРАВ // ЗАКРИТИ В АРХІВ` — фіналізація замовлення.

### 3.5. Безпековий Декой (Rickroll Honeypot)
* Усі запити до публічного порту 8080, що не входять до дозволеного переліку публічних шляхів (наприклад, спроби звернення до `/admin`, `/terminal`, `/dispatcher`, `/api/admin/*`, спроби перегляду конфігів чи пошуку вразливостей), автоматично отримують `HTTP 301 Moved Permanently` на відео-декой Rick Astley.

### 3.6. OCR Сканер Рецептів (`scripts/cqd-ocr.py`)
* Python-скрипт з підтримкою розпізнавання паперових технологічних карт та рецептів через Tesseract OCR.
* Автоматично парсить ім'я клієнта, назву фарби/штукатурки, базу та кількість відер і відправляє готовий JSON до API диспетчера.

## 4. Дизайн-система Nothing

Інтерфейс повністю спроєктований за гайдлайнами промислової естетики **Nothing**:
* **Колірна палітра:**
  * Чистий чорний бекграунд: `#000000` з напівпрозорою матричною сіткою крапок `radial-gradient`.
  * Поверхні карток: `#0e0e0e` та `#141414` з тонкими субмікронними бордерами `rgba(255, 255, 255, 0.08)`.
  * Фірмовий червоний гліф-акцент: `#d71921` з неоновим свіченням.
* **Типографіка:**
  * `Unbounded` (Google Fonts, 700–900) — акцентні заголовки та імена клієнтів з рідною підтримкою кирилиці.
  * `Doto` (Google Fonts, 800–900) — крапковий матричний шрифт для таймерів, цифр та лічильників.
  * `Space Grotesk` — інформативні блоки та поля введення.
  * `Space Mono` — технічні індикатори, бази відер та мітки статусів.
* **Адаптивність:** повна підтримка екранів від компактних смартфонів (320px–390px) до 4K-диспетчерських моніторів без розривів слів і переповнення контейнерів.
* **Футер проєкту:** фірмовий блок `Made For STEN // ПЕТ-ПРОЄКТ ДЛЯ СЕБЕ // НЕ ДЛЯ КОМПАНІЇ`.

## 5. Технологічний стек

| Компонент | Технологія | Призначення |
| :--- | :--- | :--- |
| **Backend Core** | Rust 2024 / Axum 0.8 / Tokio | Високопродуктивний асинхронний веб-сервер |
| **База даних** | SQLite 3 (rusqlite) у режимі WAL | Надійне зберігання замовлень, історії та push-підписок |
| **Статика** | `rust-embed` | Компіляція HTML, CSS, JS та іконок безпосередньо в бінарний файл |
| **Push Engine** | `web-push` + OpenSSL vendored | Генерація ECDSA VAPID JWT-токенів та доставка Web Push |
| **Криптографія** | SHA-256 + HMAC-SHA256 | Незмінний ланцюжок аудиту подій (blockchain-like audit log) |
| **Середовище** | Proxmox VE / Alpine Linux LXC | Легковажний ізольований контейнер (CT 114) |
| **Збірка** | `x86_64-unknown-linux-musl` | 100% статичний бінарник без зовнішніх бібліотек |

## 6. Локальний запуск та розгортання

### 6.1. Локальна збірка (статичний musl-бінарник)
```bash
# Додати musl таргет для rustup (якщо ще не додано)
rustup target add x86_64-unknown-linux-musl

# Перейти в каталог проєкту
cd cqd

# Збірка оптимізованого релізного бінарника
cargo build --release --target x86_64-unknown-linux-musl
```
Готовий виконуваний файл розташований за адресою:
`cqd/target/x86_64-unknown-linux-musl/release/cqd`

### 6.2. Запуск сервісу
```bash
# За замовчуванням використовуються вбудовані тестові VAPID ключі
export PUBLIC_BIND="0.0.0.0:8080"
export LOCAL_BIND="0.0.0.0:8081"
export CQD_DB_PATH="./cqd.db"

# Запуск бінарника
./target/x86_64-unknown-linux-musl/release/cqd
```

Після запуску доступні інтерфейси:
* **Публічне Табло Черги:** `http://localhost:8080/`
* **Диспетчерська Панель:** `http://localhost:8081/dispatcher`
* **Термінал Колориста:** `http://localhost:8081/terminal`

### 6.3. Розгортання на контейнері Proxmox (Alpine Linux LXC)
```bash
# Копіювання бінарника на хост Proxmox
sshpass -p 'ПАРОЛЬ' scp target/x86_64-unknown-linux-musl/release/cqd root@<PROXMOX_HOST_IP>:/tmp/cqd

# Зупинка сервісу, оновлення бінарника в CT 114 та запуск
sshpass -p 'ПАРОЛЬ' ssh root@<PROXMOX_HOST_IP> "
    pct exec 114 -- rc-service cqd stop && \
    pct push 114 /tmp/cqd /usr/local/bin/cqd && \
    pct exec 114 -- chmod +x /usr/local/bin/cqd && \
    pct exec 114 -- rc-service cqd start && \
    pct exec 114 -- rc-service cqd status
"
```

## 7. Специфікація API

### Публічні ендпоінти (Порт 8080 — WAN)
| Метод | Шлях | Опис |
| :--- | :--- | :--- |
| `GET` | `/` | Головна сторінка публічного табло черги |
| `GET` | `/api/public/queue` | JSON списку активних замовлень у черзі |
| `GET` | `/track/{token}` | Сторінка персонального трекінгу клієнта |
| `GET` | `/api/public/orders/{token}` | Дані конкретного замовлення за токеном (включно з VAPID-ключем) |
| `POST`| `/api/public/orders/{token}/subscribe` | Реєстрація Web Push підписки клієнта |
| `GET` | `/sw.js` | Service Worker для отримання фонових Push-повідомлень |
| `GET` | `/manifest.json` | Web App Manifest |
| `*`   | `/*` (Fallback) | 301 Перенаправлення на Rickroll Honeypot |

### Внутрішні ендпоінти (Порт 8081 — LAN ONLY)
| Метод | Шлях | Опис |
| :--- | :--- | :--- |
| `GET` | `/terminal` | Сенсорний термінал колориста |
| `GET` | `/dispatcher` | Диспетчерська панель керування |
| `GET` | `/admin` | Альтернативний маршрут до диспетчерської панелі |
| `GET` | `/api/admin/orders` | Отримання списку активних партій |
| `POST`| `/api/admin/orders` | Створення та реєстрація нової партії в черзі |
| `GET` | `/api/admin/archive` | Перегляд архіву завершених замовлень |
| `DELETE`| `/api/admin/orders/{id}` | Видалення партії (з черги або з архіву) |
| `POST`| `/api/terminal/orders/{id}/accept` | Взяття замовлення в роботу колористом |
| `POST`| `/api/terminal/orders/{id}/finish-bucket`| Фіксація завершення змішування відра (`+1 ВІДРО`) |
| `POST`| `/api/terminal/orders/{id}/decrement-bucket` | Відкат помилково зарахованого відра (`-1 ВІДРО`) |
| `POST`| `/api/terminal/orders/{id}/ready` | Переведення партії у стан `ГОТОВО` з надсиланням Web Push |
| `POST`| `/api/terminal/orders/{id}/delivered`| Перенесення замовлення в архів (клієнт забрав продукцію) |

## 8. Універсальність та як адаптувати під себе

Хоча система спочатку створювалася під процеси колірування Ceresit, її архітектура є **універсальним рушієм живої черги** для будь-якої фізичної майстерні або бізнесу послуг:
* **Автомийки, детейлінг та шиномонтаж:** облік авто на постах, статус готовності для водіїв зі сповіщенням на смартфон без дзвінків.
* **Кав'ярні, пекарні, крафтова піца:** табло видачі та прогрес приготування кожної одиниці замовлення.
* **Сервісні центри та ремонт техніки:** відстеження статусів діагностики, заміни деталей та готовності до видачі.
* **Склади та пункти видачі інтернет-замовлень:** монітор черги комплектації та інформування експедиторів.

Ви можете змінити найменування матеріалів та статуси безпосередньо у шаблонах `cqd/static/` і перезібрати бінарник однією командою `cargo build --release`.

## 10. Мережеві правила та MikroTik Safe Mode

Відповідно до інженерного регламенту експлуатації мережевої інфраструктури проєкту:
* **Обов'язковий Safe Mode на MikroTik:** під час будь-яких налаштувань, змін у фаєрволі (`/ip firewall`), маршрутизації (`/ip route`), інтерфейсах або правилах прокидання портів на обладнанні MikroTik RouterOS — **завжди** вмикати та використовувати режим безпеки (`Safe Mode`), щоб уникнути втрати доступу та блокування маршрутизатора.
* Заборонено застосовувати потенційно деструктивні команди без активного захисного механізму автоматичного відкоту.
* Порт `8081` суворо обмежений довіреним сегментом LAN і ні за яких умов не публікується у відкритий інтернет.
